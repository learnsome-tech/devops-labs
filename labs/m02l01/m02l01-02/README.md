# m02l01-02 · The twelve, by name and in order

**Check:** Read along

## Goal

You can state the first two factors in the manifesto's own words, tell a codebase from a deploy, and explain why declaration without isolation is not enough.

In the lesson: Here they are, in the order the manifesto gives them, with each rule in its own words. Codebase. Dependencies. Config. Backing services. Build, release, run. Processes. Port binding. Concurrency. Disposability. Development and production parity. Logs. Admin processes. Read them once and they sound obvious. The reason they are worth a module is that every violation you will meet in real code was once a reasonable decision, and the manifesto's value is in the specific, unglamorous detail of why each shortcut costs you later. We have a sample service in the lab that breaks all twelve, and a second one that satisfies all twelve.
